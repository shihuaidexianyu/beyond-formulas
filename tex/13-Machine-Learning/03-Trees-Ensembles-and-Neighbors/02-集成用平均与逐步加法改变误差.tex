\section{集成用平均与逐步加法改变误差}
\label{sec:13-Machine-Learning/03-Trees-Ensembles-and-Neighbors/02}

上一节结尾留下的那个毛病，你现在应该已经在实验记录里见过好几次了：同一份数据，换个随机种子重新划分训练集，长出来的树连根节点用哪个特征都不一样，验证集上的分数在几个百分点之间来回晃。你试过剪枝、压深度、抬高最小叶样本数，波动确实小了，可预测也跟着变钝——粗糙的树把该分开的人群按在了同一个叶子里。

你被困在一个架构里：只有一棵树可调，而方差和偏差得靠同一组旋钮同时管。旋钮往左，方差降偏差升；往右，反过来。有没有办法把这两件事拆开，交给不同的机制去做？

集成给出的答案是养很多棵树。但``很多棵树''之下藏着两条完全不同的路线，它们动的是误差的不同部分。

\subsection{相关性决定平均能省下多少方差}

先算一笔账。设有 \(M\) 个回归预测器，在某个固定的 \(x\) 处各自的预测方差都是 \(\sigma^2\)，两两相关系数都是 \(\rho\)。平均预测

\[
\bar f(x)=\frac1M\sum_{m=1}^{M}f_m(x)
\]

的方差可以直接从协方差矩阵求和得到：

\[
\Var\bigl(\bar f(x)\bigr)
=\frac{1}{M^2}\Bigl(M\sigma^2 + M(M-1)\rho\sigma^2\Bigr)
=\rho\sigma^2 + \frac{1-\rho}{M}\sigma^2 .
\]

这个式子把话说得很干脆。若所有预测器完全一致，\(\rho=1\)，右边等于 \(\sigma^2\)，把同一个模型复制一万份再平均，得到的还是它自己。若 \(\rho<1\)，第二项随 \(M\) 增大而消失，剩下 \(\rho\sigma^2\) 这个地板——成员之间共同波动的那部分，平均永远洗不掉。

于是集成的关键问题不是``要几棵树''，而是``怎样让树彼此不像''。加树只在啃第二项，越加边际收益越小；把 \(\rho\) 压下去才是在挪地板。制造分歧的手段无非三类：扰动数据、扰动算法、扰动特征空间。注意平均没碰到期望——\(\E[\bar f(x)]=\E[f_1(x)]\)，偏差原封不动。这一点和\hyperref[sec:11-Mathematical-Statistics/02-Point-Estimation/01]{``偏差、方差与均方误差''}里的分解完全对得上。

\subsection{Bagging 用重采样制造分歧}

Bagging 的做法直白：从训练集里有放回地抽 \(n\) 个样本得到一份 bootstrap 副本，在每份副本上独立长一棵树，回归取平均、分类投票。

单个样本不被某次抽样选中的概率是 \((1-1/n)^n\)，于是一份副本覆盖的原始样本比例约为

\[
1-\Bigl(1-\frac1n\Bigr)^{n}\longrightarrow 1-e^{-1}\approx 0.632 .
\]

剩下那 36.8\% 的样本对这棵树而言是没见过的。把它们攒起来，对每个样本只用没训练过它的那些树来预测，就得到 out-of-bag 误差，一个不额外划分数据就能拿到的泛化估计。

但重采样的语义得记牢：它模拟的是训练数据本身的抽样波动，并没有凭空造出新信息，详见\hyperref[sec:11-Mathematical-Statistics/06-Resampling-and-Model-Selection/01]{``Bootstrap 近似估计量的抽样波动''}。这也解释了 Bagging 挑食的原因。基学习器若本来就稳，比如一个低维线性回归，重采样后拟合出的系数几乎不动，\(\rho\) 贴近 1，平均白做。深树恰好相反，数据微扰就换结构，\(\rho\) 天然不高，平均的收益立竿见影。

\subsection{随机森林在特征上再砍一刀相关性}

设想数据里有一个特别强的特征，几乎每份 bootstrap 副本上它都稳坐根节点。各棵树的上层结构因此高度雷同，\(\rho\) 卡在一个不低的值上，方差削减很快触底。

随机森林的补丁打在节点内部：每次选切分时，只允许随机抽出的 \(m_{\text{try}}\) 个特征进入候选池。强特征有时不在池里，别的特征就有机会上位，树与树的结构分岔提前发生。这么做通常会让单棵树略微变差——最优切分被随机排除了几次——但 \(\rho\) 的下降往往买得回来还有余。\(m_{\text{try}}\) 因此是个两头受挤的参数：太小，每棵树弱到平均也救不回；太大，树又长得太像。

\subsection{特征重要性在两个地方各偏一次}

随机森林顺手给出的``特征重要性''很招人喜欢，因为它像是免费的解释。可它偏得相当系统，而且两种常见算法偏的原因还不一样。

第一种是不纯度重要性，把一个特征在所有树的所有节点上累计的 \(\Delta I\) 加起来。上一节提过，经验不纯度下降偏爱取值多的特征：连续变量和高基数类别变量有海量候选阈值，光凭挑选的自由度就能在训练集上刮出一点收益，哪怕它和响应毫无关系。把一列纯随机的连续噪声和一个二值的真实预测因子放在一起跑，噪声那列的排名常常并不靠后。偏好来自``最大化 \(\Delta I\)''这个操作本身，与树多不多无关，加树只会让它更稳定地偏。

第二种是置换重要性，把某一列打乱再看误差涨多少。它躲开了候选数的问题，却撞上相关性。两个高度相关的特征互为替身，打乱其中一个，树可以顺着另一个走完几乎相同的路径，误差涨幅很小；于是一对都重要的特征，各自的置换重要性都很低。反过来，打乱一列会造出训练数据里从未出现过的特征组合，模型在这些点上是外推的，误差上升有一部分是外推失败而非该特征的信息含量。

能做的事情有几条，代价各不相同：

\begin{itemize}
\tightlist
\item
  置换必须在留出数据上做，训练集上的置换重要性会把过拟合读成重要性；
\item
  先按相关结构把特征聚成组，整组一起置换，报告组级重要性，替身效应就消失了；
\item
  条件置换在同一列的分层内部打乱，保留与其他特征的联合分布，避免制造不存在的组合；
\item
  真要问``去掉它模型会差多少''，就把这列删掉重训一遍，语义最干净，代价是每个特征一次完整训练；
\item
  给数据加一列已知无关的随机变量当标尺，凡是排名没显著超过它的特征，就别当真。
\end{itemize}

无论用哪一条，得到的都是``该模型对该特征的依赖程度''，与``该特征是否为原因''之间隔着一整套额外假设。

\subsection{Boosting 沿损失的梯度逐步纠偏}

Bagging 的成员可以完全并行，谁先训练无所谓。Boosting 反过来，每一棵新树都要看着前面所有树留下的残余误差来定自己的目标。

考虑加法模型

\[
F_M(x) = F_0(x) + \sum_{m=1}^{M} \eta\, h_m(x).
\]

在平方损失下，第 \(m\) 轮的残差为 \(r_i^{(m)} = y_i - F_{m-1}(x_i)\)，训练一棵小树 \(h_m\) 去拟合这些残差，再更新 \(F_m = F_{m-1} + \eta h_m\)。为什么是残差？把损失对预测值求导就明白了：

\[
\left.\frac{\partial}{\partial F(x_i)}\;\frac12\bigl(y_i-F(x_i)\bigr)^2\right|_{F=F_{m-1}}
= -\bigl(y_i - F_{m-1}(x_i)\bigr).
\]

拟合残差等于沿负梯度方向走。换成一般的可微损失 \(\ell\)，把目标改成

\[
r_i^{(m)} = -\left.\frac{\partial \ell\bigl(y_i, F(x_i)\bigr)}{\partial F(x_i)}\right|_{F=F_{m-1}}
\]

就得到 gradient boosting：在函数值构成的空间里做梯度下降，只不过每一步的方向要先被投影回``树能表达的函数''这个受限集合。学习率 \(\eta\) 扮演的角色和\hyperref[sec:09-Convex-Optimization/06-Optimization-Algorithms/01]{``梯度下降真正难在步长''}里的步长一致，太大会越过去，太小要走很久。

\(\eta\)、单树深度、总轮数三者联合决定了模型的有效复杂度。浅树限制单步能捕捉的交互阶数，小 \(\eta\) 让每步修正温和，轮数则决定总共修了多远。训练损失通常随轮数单调下降，验证损失却会在某一轮掉头向上——这个转折点必须由一份没参与拟合的数据来指认，跑完全程画出验证曲线再回头挑最低点，等于让那份数据参与了训练。把早停放进交叉验证的内层，做法见\hyperref[sec:11-Mathematical-Statistics/06-Resampling-and-Model-Selection/03]{``交叉验证评估的是完整训练流程''}。

\subsection{两条路线降的是误差的不同部分}

\emph{左边平均只压散布不挪中心，右边每一步都在挪中心，多走几步就开始跟着噪声抖。}

左边那团点是 \(M\) 棵 bagged 树各自的预测，虚线圈是它们的散布，实心方块是平均。加树把圈收紧，方块却纹丝不动——它到叉号的那段距离是偏差，重采样碰不到它。所以 Bagging 不会因为树多而过拟合：把 \(M\) 从 100 调到 1000，验证误差会趋于平稳而不会掉头，多花的只是算力。它失效的样子是``怎么加树都不再变好''，此时该查的是基学习器的偏差，或者树间相关是否已经触底。

右边是 Boosting 的轨迹。起点是一个粗糙的常数模型，偏差很大，每一步朝着当前梯度方向挪一小段。虚线的两步是走过头之后的样子：训练集上的残差已经主要由噪声构成，而算法照旧忠实地去拟合它们。这里藏着 Boosting 最具体的脆弱点——错标的样本。一个真实类别是 A 却被记成 B 的点，无论模型怎么调整都留着大残差，于是它在后续每一轮里都获得最高的目标权重，一棵接一棵的树被派去围剿这一个点，最终在它周围切出一小块专属区域。指数损失下这种放大尤其猛烈，因为权重随间隔指数增长。缓解的思路是别让单点的影响无限放大：换 Huber 或分位数这类对大残差饱和的损失、限制单个叶子的输出幅度、每轮只用一部分样本和特征、把 \(\eta\) 调小并靠轮数补回来。

所以``多棵树投票''这个说法抹掉了要紧的区别。Bagging 要的是成员之间足够不像而各自不太偏，它的旋钮是相关性；Boosting 要的是每一步修正足够温和而不跑过头，它的旋钮是步长与轮数。诊断的方向也随之分开：验证误差随树数单调趋平却停在高位，是偏差主导，该换更强的基学习器或改用 Boosting；验证误差先降后升，是走过了头，该回到早停、学习率和标签质量上找原因。
