\section{损失、风险、目标与指标不是同一个量}
\label{sec:13-Machine-Learning/01-Learning-Problems-and-Evaluation/02}

\subsection{一个训练脚本里的四重身份}

一家支付公司的风控团队用半年交易记录训练了一个欺诈检测模型。训练日志显示交叉熵从 0.693 一路降到 0.087，验证集 accuracy 停在 94.3\%。团队把模型推上线，每天自动标记 200 笔可疑交易供人工复核。

第一周结束后，运营组反馈：每天标记的 200 笔里，确实欺诈的只有 3 笔；而同期另有 12 笔欺诈交易根本没被标记，直接完成了划转。\textbf{训练损失降了 87\%，线上拦截率几乎没有变化。}

团队的第一反应是优化器没调好。换了 AdamW，加了三层残差连接，训练损失进一步压到 0.042，验证 accuracy 升到 95.1\%。线上表现纹丝不动。

又怀疑是数据不够。把训练数据从半年扩展到两年，样本量从 80 万增加到 320 万。交叉熵降到 0.031，accuracy 到 95.8\%。线上拦截率仍然没有实质变化。有人提出换用 focal loss，给难分类样本更高权重——训练损失降到 0.018，但线上还是没有改善。

这时候才有人问了一个绕不过去的问题：损失函数在不停地下跌，优化器忠实地完成了交给它的数值任务，但那个任务本身真的是我们想解决的问题吗？0.042 这个数到底测量了什么？它下降说明什么变好了？而风控部门真正关心的——拦截欺诈、减少资金损失、控制人工审核成本——又是完全不同的另外几个量。

答案藏在四个被混用的概念里。训练脚本里它们可能只差几行代码，例如
\[
\begin{gathered}
\texttt{criterion = nn.CrossEntropyLoss()},\qquad
\texttt{loss = criterion(y\_pred, y\_true)},\\
\texttt{val\_loss = ...},\qquad
\texttt{metrics.accuracy = ...}.
\end{gathered}
\]
但数学上它们住在不同的空间，面对不同的随机性，服务于不同的决定。把损失函数的值、分布上的期望风险、优化器在跑的目标函数和最终报告的评估指标混为一谈，等于用同一把尺子去量温度、湿度、气压和风速，然后说它们都是``环境数据''。

\subsection{损失：一个预测、一次代价}

对单个样本，预测 \(f(x)\) 与真实结果 \(y\) 之间的代价写作
\[
\ell(f(x),y).
\]

平方损失 \((f(x)-y)^2\) 对大误差惩罚是二次增长的——残差从 2 变到 4，损失不是翻倍而是翻四倍。绝对损失 \(\abs{f(x)-y}\) 对大误差的惩罚与距离成正比，不会给离群值额外加权。对数损失 \(-\log p_{\text{model}}(y\mid x)\) 按模型分配给真实结果的概率计费：若模型对正确结果只分配了 0.01 的概率，这一笔损失就是 \(-\log(0.01)\approx 4.6\)；若分配了 0.9，损失只有 \(-\log(0.9)\approx 0.105\)。

损失的形状决定了训练时哪些错误会被优先修正。但同一组 \((x,y)\) 可以有几个合理的损失，它们回答不同的问题。

若 \(Y\mid X=x\) 的分布偏斜，平方损失的总体最优预测是条件均值 \(\E[Y\mid X=x]\)，绝对损失的总体最优预测是条件中位数。两者都没算错——它们只不过在估计不同的统计量。

举一个离数学不远的具体场景。一家便利店每天下午五点前要决定次日面包订货量 \(q\)。需求 \(D\) 还没发生。每剩一条面包，报废成本 \(c_{\mathrm o}=4\) 元；每缺一条面包，缺货损失（顾客不满加流失）折合 \(c_{\mathrm u}=16\) 元。给定天气预报、星期几和周边活动信息 \(X=x\) 后，条件需求分布偏右——大多数日子卖出 80--120 条，但遇到球赛可能冲到 200 条以上。

给定 \(x\)，选择订货量 \(q\) 的条件风险是
\[
C(q\mid x)
=c_{\mathrm o}\E[(q-D)_+\mid X=x]
+c_{\mathrm u}\E[(D-q)_+\mid X=x].
\]

第一项是报废的期望成本，第二项是缺货的期望成本。若条件需求的累积分布函数 \(F(\cdot\mid x)\) 连续，对 \(q\) 求导：
\[
\frac{\partial C(q\mid x)}{\partial q}
=c_{\mathrm o}F(q\mid x)
-c_{\mathrm u}\bigl(1-F(q\mid x)\bigr).
\]

令导数为零，最优订货量满足
\[
F(q^\star\mid x)
=\frac{c_{\mathrm u}}{c_{\mathrm u}+c_{\mathrm o}}=\frac{16}{16+4}=0.8.
\]

条件均值订货会把报废和缺货的总成本推到比最优水平高出 15\%--30\%（具体数值取决于分布的偏斜程度）。缺货越昂贵，所需分位数越高。在这种情况下，损失函数不是在调参数——它从一开始就在选择模型要去学哪个统计量。先写出行动损失，才知道模型该学均值、中位数还是第 80 百分位数。

\subsection{风险：把代价摊到未来分布上}

损失衡量单个结果。但我们真正想控制的，是预测器在所有未来场景中的预期表现。若部署时数据来自分布 \(P\)，预测器 \(f\) 的总体风险是
\[
R_P(f)=\E_{(X,Y)\sim P}\bigl[\ell(f(X),Y)\bigr].
\]

这是最终想控制的量，但通常无法直接计算——未来总体分布 \(P\) 未知。手头只有训练数据
\[
S=\{(x_i,y_i)\}_{i=1}^n,
\]

于是用经验风险近似：
\[
\widehat R_S(f)=\frac1n\sum_{i=1}^n\ell(f(x_i),y_i).
\]

对一个在见到数据之前就固定好的 \(f\)，当样本独立同分布且损失可积时，经验风险是总体风险的无偏估计。大数定律保证它会收敛到 \(R_P(f)\)。

但训练不是拿一个预先固定的 \(f\) 去评估。训练是从函数类中\emph{选出}那个让经验风险最小的 \(\widehat f\)——而挑选本身就消耗了样本中的随机性。设想你在 100 个候选函数中挑出训练误差最小的那个：即使所有候选函数的真实风险完全相同，由于训练数据中的抽样波动，总会有一个碰巧在这份具体数据上表现最好。你把那个挑出来，但它不是泛化更好，只是在训练噪声上更幸运。结果是 \(\widehat R_S(\widehat f)\) 系统性地低于 \(R_P(\widehat f)\)。这就是为什么训练误差几乎总是乐观的：同一个数据集既被用来挑函数，又被用来给这个函数打分，两次使用了同一份噪声。

风险还必须在分布上标明下标。若训练分布 \(P_{\mathrm{train}}\) 与部署分布 \(P_{\mathrm{deploy}}\) 不同，即使样本量趋于无穷，训练经验风险也只会逼近 \(R_{P_{\mathrm{train}}}(f)\)，而不会自动逼近 \(R_{P_{\mathrm{deploy}}}(f)\)。

回到便利店的例子。数据库记录的是销量 \(S\)，而不是真实需求 \(D\)。库存为 \(I+q\) 时，
\[
S=\min\{D,\,I+q\}.
\]

售罄日的数据只告诉你需求至少达到了库存量，没告诉你它超出了多少。若直接把销量当需求训练模型，模型会系统性地低估旺盛需求，于是少订货、制造更多售罄记录、进一步压低未来的``需求''数据。这里的误差不在随机波动范围内——历史订单已经决定了标签能被观察到多少，训练分布与部署分布的差异从行动路径进入了数据生成机制。

\subsection{训练目标：在风险之上再加选择}

实际跑优化时，目标函数通常不只包含经验风险：
\[
J_S(\theta)
=\widehat R_S(f_\theta)+\lambda\Omega(\theta).
\]

第一项让模型拟合数据，第二项通过范数惩罚、稀疏约束或其他结构限制来缩小候选模型的范围。\(\Omega(\theta)\) 可能表达对平滑性的偏好（L2）、对稀疏性的偏好（L1）、对群组结构的偏好，或者同时承担以上多个角色。

\(J_S(\theta)\) 不是任何一个未来样本上的损失，也不等于部署风险。正则项改善的是从有限样本中选出稳定函数的概率，而不是让函数在总体分布上更正确——它用偏差换方差，前提是这个交换在未见数据上产生更小的期望误差。

训练目标还可能使用代理损失。分类问题真正关心的往往是 \(0\)-\(1\) 错误：
\[
\ell_{01}(f(x),y)=\ind\{f(x)\ne y\}.
\]

直接优化它极度困难——目标函数分段常数，梯度几乎处处为零。几乎任意两个候选预测器的 \(0\)-\(1\) 损失都是相同的（都分错了一些样本），优化器不知道该往哪个方向移动。于是改用 logistic loss、交叉熵或 hinge loss 作为替代。这些替代损失有几个共同的好处：光滑、凸、可导，局部梯度给出明确的搜索方向。但它们也有各自的副作用：logistic loss 对已经正确分类的样本仍然施加非零的惩罚（它鼓励预测器不仅分对、还要分得有把握），hinge loss 对离决策边界足够远的正确分类样本零梯度（一旦分对就不再推动预测器远离边界）。

这些替代损失在一定条件下与 \(0\)-\(1\) 损失有相同的总体最优解（即 Bayes 分类器），但这种一致性需要条件——通常要求函数类足够灵活、数据量足够大、噪声条件符合替代损失的内在假设。若类别严重不平衡、代价不对称或决策阈值不取 \(1/2\)，替代损失的最优解可能偏离真正关心的决策边界。选择替代损失时，不能只因为它``方便优化''就默认它与最终目标一致——需要检查替代损失在具体数据分布和函数类下是否真的把你引向正确的方向。

优化算法是寻找较小 \(J_S\) 的数值过程。SGD、Newton、坐标下降、Adam 解决的是同一个目标上的不同搜索策略。优化到机器精度，不能修复损失定义错误、数据泄漏或分布选错——它只是忠实地完成了交给它的数值任务。

\subsection{指标：压缩一组预测，保留部分信息}

评价指标把一堆预测值压缩成少数几个便于比较的数字。Accuracy、precision、recall、F1、ROC AUC、均方误差、校准误差分别保留和丢弃不同的信息。一个指标改善，不意味着所有指标都改善，也不意味着部署效果改善。理解每个指标的立场，才能判断它是否代表你真正在意的后果。

类别极不平衡时，这个现象最直观。若 98\% 的交易是正常的，恒预测``正常''能拿到 98\% accuracy——比大多数精心训练的模型都高。但这个预测器从未标记过任何一笔欺诈，recall 为零，在风控中的实际价值也为零。Accuracy 把两类错误等权重相加，而当类别比例悬殊时，它完全被多数类主导。一个模型把 accuracy 从 98.2\% 提升到 98.7\%，看起来是 0.5 个百分点的进步，但这 0.5 个百分点可能来自正确分类了更多正常交易——而在欺诈检测上毫无变化甚至退化。

AUC（ROC 曲线下面积）衡量的是：随机抽一个正例和一个负例，模型给正例的分数高于负例的概率。它有一个很好的性质——不依赖阈值，也不受类别先验比例影响。但 AUC 也有它不告诉你的事。一个 AUC 为 0.95 的模型，可以把所有正例排在 0.51--0.55 的分数区间、所有负例排在 0.50 以下——排序正确，但分数差距极小，任何一个扰动都可能翻转排序。AUC 也不告诉你模型在排序顶部的 precision 是多少：如果每天只复查 200 笔，你需要的是模型对最可疑的那 200 笔判断极准，而这个信息不在 AUC 里。

F1 是 precision 和 recall 的调和平均。调和平均（而不是算术平均）意味着只有当两者都高时 F1 才高——precision 为 0.9、recall 为 0.1 时 F1 仅为 0.18，而不是算术平均的 0.5。F1 完全忽略 true negative——正常交易被正确放行不会改善 F1。在欺诈检测中这或许是合理的（正常交易太多，计入它们会淹没信号），但在疾病筛查中漏掉一个阴性病例可能同样危险，true negative 是有价值的正确决策。F1 的选择本身就是一个立场声明：false positive 和 false negative 等权重，true negative 不计入质量评估。

多个群体上的平均指标还会掩盖分布差异。总体 accuracy 可以从 94\% 提升到 95\%，同时新注册用户群体的 accuracy 从 88\% 掉到 82\%——总体的上升完全来自老用户群体的改善，新用户的体验在退化而你从汇总数字中看不到。微平均（micro-average）把每个样本等权加总，结果被大群体主导；宏平均（macro-average）把每个群体的指标先各自计算再平均，赋予所有群体等权重。选择哪种平均，取决于你认为每个样本应该等权重，还是每个群体应该等权重——而这两个原则在群体大小悬殊时给出相反的方向。

\subsection{阈值是被代价决定的，不是被概率模型自动输出的}

设 \(p(x)=P(Y=1\mid X=x)\) 是模型估计的条件概率。决定标记为``正类''时，若真实是负类，承担假阳性代价 \(C_{\mathrm{FP}}\)；决定标记为``负类''时，若真实是正类，承担假阴性代价 \(C_{\mathrm{FN}}\)。给定 \(x\)，两种行动的条件风险分别是
\[
\begin{aligned}
\rho(1\mid x)&=C_{\mathrm{FP}}\bigl(1-p(x)\bigr),\\
\rho(0\mid x)&=C_{\mathrm{FN}}\,p(x).
\end{aligned}
\]

选择正类当且仅当 \(\rho(1\mid x)\le\rho(0\mid x)\)，即
\[
p(x)\ge
\frac{C_{\mathrm{FP}}}{C_{\mathrm{FP}}+C_{\mathrm{FN}}}.
\]

只有两种错误代价相等时，阈值才是 \(1/2\)。回到欺诈检测：漏掉一笔欺诈的代价可能是错误冻结一笔正常交易的 50 倍，这个比值把阈值拉到了 \(50/(50+1)\approx 0.98\) 以下。概率模型的任务是输出校准良好的 \(p(x)\)，决策层再结合代价选择阈值。若模型输出的只是排序分数而非校准概率，上述阈值公式甚至不能直接使用。

代价还可能随 \(x\) 变化，也可能受容量约束。一家医院每天只能安排 40 个复查名额，此时决策变成了带总预算的全局分配问题，不能再对每个病人独立阈值化——必须对所有病人按风险排序，把名额分配给前 40 名。

\subsection{回到那四行日志}

现在再看风控团队遇到的情况。交叉熵从 0.693 降到 0.042，说明优化器在代理损失上做得很好。验证 accuracy 94.3\%，说明模型在等权重分类正确的意义上表现不错。但真实问题有四层错位：

第一，交叉熵鼓励模型输出校准概率，但它不区分两类错误的业务代价——把一笔正常交易标为可疑（浪费人工审核），和漏掉一笔欺诈（资金损失），在交叉熵里的惩罚是对称的。

第二，94.3\% accuracy 中大约 96 个百分点来自正确放行的正常交易。模型完全可能只抓到了 20\% 的欺诈交易，accuracy 依然很高。

第三，训练目标里的 L2 正则化在把概率向 0.5 方向拉扯，对于本来应该接近 0 或 1 的极端样本，这种收缩降低了模型区分能力。

第四，运营团队每天只能复核 200 笔，这个容量约束根本没有进入任何损失函数或评价指标。

\subsection{四件事，四个检查}

看到目标下降而部署效果没变化时，分别追问：

\begin{itemize}
\tightlist
\item
  样本损失惩罚了哪类错误？它对应的最优预测是均值、中位数、分位数还是概率——这正是你希望模型去学的那个统计量吗？
\item
  风险是对哪个分布取期望？训练样本来自那个分布吗？标签有没有被历史行动截断？
\item
  训练目标额外加了什么正则化或近似？它改变了最小化的问题本身，还是在原问题里加了约束？
\item
  报告指标保留和丢弃了什么信息？若代价不对称、群体有差异或存在容量约束，这个指标还能不能为行动提供正确排序？
\end{itemize}

这四层在一次训练里可能挤在同一个 Python 文件的相邻行里，但数学上它们是不同对象。把其中一层修好，不自动修好另外三层。而如果连哪一层出了问题都分不清，下一步该往哪个方向走也就无从判断。
