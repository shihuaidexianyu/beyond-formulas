\section{递归定义与结构归纳}
\label{sec:01-Mathematical-Language/04-Induction-and-Recursion/03}

\subsection{想定义无限个对象，但只允许写有限行字}

试着定义``所有合法的算术表达式''。你可以这样含糊地说：变量和常数是表达式；两个表达式用 \(+\) 或 \(\times\) 连接起来也是表达式。这听上去好像已经把话说清楚了。

但这句话其实藏了一个问题：你定义``表达式''的时候，用了``表达式''这个词本身。如果对方追问``那到底什么才算表达式''，你只能说``就是那些能被这几条规则生成出来的东西''。这在逻辑上叫自指，但如果把规则写对，自指并不会产生矛盾——反而是一个极为精确的描述方式。

关键是你需要三样东西：

\begin{enumerate}
\tightlist
\item
  基础对象：不用借助任何其他对象就能判定为合法的那些。比如单独的变量 \(x\)、常数 \(3\)。
\item
  构造规则：从已有的合法对象造出新的合法对象。比如如果 \(E_1\) 和 \(E_2\) 都是表达式，那么 \((E_1+E_2)\) 也是表达式。
\item
  封闭条款：除了上面两条规则生成的东西，没有其他表达式。这一条往往不写出来，但没有它定义就漏了边界——万一有人声称某个奇怪的东西也算表达式，你得有依据说它不是。
\end{enumerate}

这三条合在一起，形成了递归定义的标准模板：用有限条规则，钉死一个无限集合的边界。这就是你能在有限篇幅内精确谈论无限对象的机制。

\subsection{熟悉的老面孔：定义数列}

阶乘的递归定义应该是最早见过的例子之一：

\[
0! = 1, \qquad (n+1)! = (n+1)\, n!.
\]

第一条是基例——告诉你在 0 那里停住，不用再往后退。第二条是一条归约规则——把 \((n+1)!\) 的计算责任转交给 \(n!\)。如果只写 \(n! = n(n-1)!\) 却忘了写 \(0!\) 是什么，计算会永无止境地向更小的下标退行，永远落不了地。

Fibonacci 数列也是同一套模板：

\[
F_0 = 0, \quad F_1 = 1, \quad F_n = F_{n-1} + F_{n-2}\;(n\ge 2).
\]

前两个值是基例（这次有两个基例，因为递推式回望了两步），第三个是构造规则。

顺便提一件容易混淆的事：这个定义准确描述了 Fibonacci 数列是什么。如果把这个定义直接翻译成代码，你会得到一个正确但极慢的程序——因为它会重复计算海量子问题。数列的数学定义、正确的算法、高效的算法，是三个可以各自独立讨论的层面。递归定义的数学功能是说清楚对象是什么，不是在推荐实现方案。

\subsection{不止数列：递归定义能造出一整类对象}

定义一个数据类型，也完全可以用递归的思路。比如二叉树：

\begin{enumerate}
\tightlist
\item
  一个单独的节点（叶子）是一棵二叉树。
\item
  如果 \(T_1\) 和 \(T_2\) 是二叉树，那么把它们分别作为左子树和右子树，挂在一个新根节点下面，得到的也是一棵二叉树。
\item
  没有其他东西是二叉树。
\end{enumerate}

用这个定义，可以一层一层地造出越来越大的树。根只带一个左叶子和一个右叶子是最小的非平凡二叉树。再往上，左子树和右子树可以是任意已有二叉树。

这种生成方式并不只活在教材上。一个产品的物料清单也是递归结构：叶子是外购的标准零件，组合件由若干子装配件加上装配工序构成。算总成本的时候，叶子的成本直接查表，组合件的成本是各子部件递归汇总加上装配费——这就是按生成规则逐层计算。要证明这个成本算法覆盖了每一份合法物料清单，证明的结构也应该和清单的递归定义同构：先证叶子情况成立，再证任何合规的组合操作不破坏结论。

现实的数据结构往往比这个理想模型复杂。如果同一个部件在多处被引用，物料清单就不再是树，而是一个有向无环图——沿装配关系走不会回到起点，但一个节点可以有多个父节点。这时递归算法得加一个备忘机制，避免对同一个部件重复计费。如果再进一步，连``不会回到起点''这个条件都被打破了——比如出现了环形依赖——递归定义本身就失去了基础情形，整个定义需要重来。对象的结构变了，递归方法和证明的边界也得跟着变。

\subsection{结构归纳：跟着对象怎么造，就怎么证}

对递归生成的对象，证明方法自然是跟着它的生成规则走。结构归纳法只有两个步骤：

\begin{enumerate}
\tightlist
\item
  基础步：验证所有基础对象（不依赖构造规则的那一批）满足性质。
\item
  归纳步：对每一条构造规则，假设该规则的各个输入对象都满足性质，然后证明该规则输出的新对象也满足性质。
\end{enumerate}

不需要先把树、串、表达式这些对象编码成自然数再套普通归纳。直接沿着对象的构造语法一层一层走上去就行。

\subsection{满二叉树的叶子与内部节点}

拿一个具体命题练手。

\begin{center}
\textbf{命题}：在任意一棵有限满二叉树（每个内部节点恰好有两个子节点）中，叶子数 \(L\) 和内部节点数 \(I\) 满足 \(L = I + 1\)。
\end{center}

先来理解一下这个结论在说什么。画一棵最小的满二叉树：只有一个根节点加上左右两个叶子。这时候内部节点就根一个，叶子有两个——\(2 = 1 + 1\)，成立。再画大一点：给左叶子加两个子节点。现在内部节点变成了根和那个新加的内部节点，共两个；叶子变成了右叶子加上新加的两个叶子，共三个。\(3 = 2 + 1\)，仍然成立。

感觉有个模式，但怎么把它变成证明？

用结构归纳。二叉树的递归定义在前面已经给出了，证明就按那两条规则来。

\textbf{基础树}（单个叶子节点）：\(L=1\)，\(I=0\)。\(1 = 0 + 1\)，公式成立。

\textbf{构造步}：取两棵二叉树 \(T_1\) 和 \(T_2\)，假设它们各自满足公式：
\[
L_1 = I_1 + 1, \qquad L_2 = I_2 + 1.
\]
把它们挂到一个新根节点下面，生成一棵新树 \(T\)。新树的叶子和内部节点计数为：
\[
L = L_1 + L_2, \qquad I = I_1 + I_2 + 1.
\]
（新根贡献了 \(+1\) 个内部节点，叶子数量就是两棵子树叶子之和。）

代进去：
\[
L = (I_1 + 1) + (I_2 + 1) = I_1 + I_2 + 2 = (I_1 + I_2 + 1) + 1 = I + 1.
\]

基础步和构造步都通过，而每一棵有限满二叉树恰好由这两条规则生成，所以结论对全部这样的树都成立。

这个证明最舒服的地方在于：不需要管树长什么形状、不需要手动去数各层有多少节点、不需要对高度做额外归纳——结构归纳直接沿树的生成语法走，每一步只处理一条构造规则。证完了你甚至觉得这不该叫证明，更像是在逐字翻译定义的逻辑后果。

\subsection{同一条河，不同的渡口}

如果同一个对象有多条不同的构造路径，递归定义就有麻烦了。

设想用分数 \(p/q\) 表示有理数。如果直接说``有理数 \(p/q\) 的某种属性定义为 \(p+q\)''，就有问题——因为 \(1/2\) 和 \(2/4\) 表示的是同一个数，而 \(1+2=3\) 不等于 \(2+4=6\)。同一条河从不同的渡口出发，走到了不同的终点。这种情况需要额外证明\emph{良定义性}——结果和所选的代表元无关。

对于表达式语法，规避这个问题的手段是强制构造路径唯一：保留括号或者保留解析树（Parsing Tree），让每个合法的表达式恰好对应一棵树。对于商结构，则需要证明选不同代表元不改变结果。总之，写下递归公式只是第一步，函数是否良好定义还有一步独立的检查。
