\section{数列怎样收敛}
\label{sec:02-Calculus/05-Sequences-and-Series/01}

一段迭代代码打印出来的值是 1.9904、1.9976、1.9994、1.9999……你要不要让程序停下来？

通常的理由是``它已经不怎么动了''。但这个经验法则极度危险：
\begin{itemize}
    \item \textbf{每步挪一点，不代表会停下}：调和级数 \(1 + 1/2 + 1/3 + \dots\) 每步增加的量越来越微小，但累积起来却可以走向无穷大；
    \item \textbf{贴近某个数，不代表能稳住}：如果奇数项取 \(2 + 1/n\)，偶数项取 \(3 - 1/n\)，奇数项无限逼近 2，但整条数列却在 2 和 3 之间永远震荡。
\end{itemize}

日志截取的那一小段变化，根本无法区分``真正停住''与``假装贴近''。因此，在给算法设定停机准则前，我们必须严谨地回答：\textbf{``稳定到某个数''究竟意味着什么？}

\subsection{把直觉翻译成数学：\(\varepsilon\)-\(N\) 语言}

为了抓住``稳定''的本质，数学家提出了一个博弈式的定义。

我们称数列 \((a_n)\) 收敛到极限 \(L\)（记作 \(a_n \to L\)），是指：
\[
\forall\varepsilon>0,\;\exists N\in\N,\;\forall n\ge N,\;\abs{a_n-L}<\varepsilon.
\]

这句话听起来很抽象，但它的核心逻辑只是一场\textbf{``误差对赌''}：
\begin{enumerate}
    \item \textbf{对方提出容忍度 (\(\varepsilon\))}：无论对方给出一个多么苛刻、多么窄的误差窗口 \(\varepsilon\)（比如 \(10^{-6}\)）；
    \item \textbf{你给出截断位置 (\(N\))}：你总能指出算法运行到第 \(N\) 步；
    \item \textbf{尾部一项不漏}：从第 \(N\) 步开始的\textbf{所有}后续项 \(a_n\)（\(n \ge N\)），无一例外地落在这个误差窗口内。
\end{enumerate}

\emph{窗口是对方给的，位置 \(N\) 是你找的。当对方把窗口缩小，你只需把 \(N\) 往后推；只要无论窗口多窄你都找得到 \(N\)，收敛就成立。}

这个定义极其苛刻，但它一刀斩断了所有伪稳定：前面的有限项可以任意剧烈震荡，但尾部必须被彻底死死控住。

基于这个定义，我们可以导出极限的关键性质：\textbf{极限如果存在，就必定唯一}（不可能同时落入两个不重叠的窄窗口）；且\textbf{收敛数列必定有界}（前面有限项有界，尾部被限制在窗口内）。

\subsection{工程难题：不知道极限时，怎么证明它稳定？}

上面的定义虽然完美，但在实际算法中存在一个致命痛点：\textbf{验证定义的前提是你已经知道了极限 \(L\) 是多少}。

但在绝大多数迭代算法中，我们手里只有一个递推公式，根本写不出极限的闭式解。例如开头打印出的那串数字，其实来自这样一个简单的递推式：
\[
a_1=0,\qquad a_{n+1}=\sqrt{2+a_n}.
\]
前几项是 \(0, 1.414, 1.848, 1.962, 1.990 \dots\)。递推式只给了我们``下一步怎么走''，却没有交代``终点在哪里''。

幸好，实数系的完备性赋予了我们一把特殊的武器——\textbf{单调有界定理}：
\begin{quote}
\textbf{只要一个实数列是单调递增且有上界的，它就必定收敛。}
\end{quote}
这把武器的厉害之处在于：\textbf{它只交付``极限一定存在''的保证，却不需要你提前算出极限是多少。}

现在，我们拿这把武器来解剖上面的递推式：
\begin{enumerate}
    \item \textbf{寻找天花板（有界性）}：直觉告诉我们数值在往 2 靠。用数学归纳法容易证明：\(a_1 = 0 \le 2\)；若设 \(a_n \le 2\)，则 \(a_{n+1} = \sqrt{2+a_n} \le \sqrt{2+2} = 2\)。因此 2 是一个严格的上界。
    \item \textbf{验证一直在前进（单调性）}：比较前后两项，考察 \(a_{n+1} - a_n\) 的符号：
    \[
    a_{n+1} \ge a_n \iff \sqrt{2+a_n} \ge a_n \iff 2+a_n \ge a_n^2 \iff (a_n-2)(a_n+1) \le 0.
    \]
    由于我们刚刚证明了 \(0 \le a_n \le 2\)，上式显然恒成立！即 \(a_{n+1} \ge a_n\)，数列单调递增。
\end{enumerate}

``单调递增''加上``有上界''，单调有界定理立刻生效：\textbf{无需知道终点在哪，我们现在可以百分之百断言，这个迭代算法必然收敛到某个极限 \(L\)。}

\subsection{避坑指南：代入极限之前的逻辑陷阱}

在确定了极限存在之后，求出具体的 \(L\) 就顺理成章了。因为 \(a_{n+1} = \sqrt{2+a_n}\)，且根号函数是连续的，我们可以两边同时取极限：
\[
\lim_{n\to\infty} a_{n+1} = \sqrt{2 + \lim_{n\to\infty} a_n} \implies L = \sqrt{2+L}.
\]
解方程得到 \(L=2\) 或 \(L=-1\)。结合非负性，排除 \(-1\)，最终确定极限 \(L=2\)。

\textbf{请特别注意这里的逻辑顺序！} 很多人喜欢直接跨过存在性证明，写下``设极限为 \(L\)，则 \(L=\sqrt{2+L}\)''。这种做法犯了逻辑上的大忌：\textbf{你在给一个尚未证明存在的对象解方程。}

考虑另一个递推式：\(a_1=1,\ a_{n+1}=2a_n\)。如果你盲目假设极限存在，写出 \(L = 2L\)，同样能解出 \(L=0\)。然而这个数列实际上爆炸式发散到无穷大！代入方程求极限，只回答了``如果极限存在它必须是什么''，却完全无法保证``它真的存在''。

\subsection{从判定方向到衡量速度}

至此，我们建立了一条完整的判定逻辑：
\begin{enumerate}
  \item 用 \textbf{\(\varepsilon\)-\(N\) 语言} 严格定义收敛；
  \item 用 \textbf{单调有界定理} 在未知极限时断言存在性；
  \item 用 \textbf{连续性方程} 求解极限的具体数值。
\end{enumerate}

但请记住，收敛性只回答了``算法最终会不会停''，却对``需要多久才能停''只字未提。例如 \(1/n\) 和 \(1/\ln n\) 最终都会走向 0，但要达到 \(10^{-3}\) 的精度，\(1/n\) 只需要 1000 步，而 \(1/\ln n\) 需要跑超过 \(e^{1000}\) 步（这是一个天文数字）。

在工程实践中，光知道收敛是远远不够的，我们还必须衡量收敛的速度。而一旦开始关注``增量的累加速度''，我们就必须从单一数列的极限，迈向下一节的核心主题：\textbf{无穷项相加的级数理论}。
