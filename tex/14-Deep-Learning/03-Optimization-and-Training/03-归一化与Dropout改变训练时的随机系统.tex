\section{归一化与 Dropout 改变训练时的随机系统}
\label{sec:14-Deep-Learning/03-Optimization-and-Training/03}

你训练了一个深层网络。验证集准确率 94.3\%，损失曲线平滑收敛到 0.21。一切正常，部署上线。第一条真实样本进来，模型输出概率 0.03——而同一个样本在验证集上给出的是 0.87。

排查清单的第一轮：权重文件完整，预处理一致，输入数值没有越界，随机种子也固定了。一切看起来都对。但问题藏在一个更底层的地方：训练时每次前向传播计算的函数，和推理时计算的函数，不是同一个函数。Batch Normalization 和 Dropout 各自在训练态塞入了随机性，而部署时这些随机性被关闭了。两个函数的距离可以大到让同一个样本的输出从确信变为茫然。

\subsection{Batch Normalization：一个样本的输出取决于同 batch 里的陌生人}

先只看一层。假设某隐藏层在第 3 个样本上的激活值是 \(x_3 = 3.7\)。你的直觉是：无论这个样本和哪些其他样本组成一个 batch，经过该层变换后输出应该只取决于 \(x_3\) 和该层参数。没有 batch 什么事。

BN 直接打破这条直觉。对一个 mini-batch 中某通道的 \(m\) 个激活 \(x_1,\ldots,x_m\)，它先算批统计量：
\[
\mu_B = \frac{1}{m}\sum_{i=1}^m x_i,
\qquad
\sigma_B^2 = \frac{1}{m}\sum_{i=1}^m (x_i - \mu_B)^2,
\]
再输出
\[
y_i = \gamma\,\frac{x_i - \mu_B}{\sqrt{\sigma_B^2 + \varepsilon}} + \beta.
\]
\(\gamma,\beta\) 是可学习参数，让网络在归一化后仍能恢复合适的尺度和位置。\(\varepsilon\) 是防除零的小常数。

现在盯着 \(y_3\) 的表达式。它里面出现了 \(\mu_B\) 和 \(\sigma_B\)，这两个值依赖整个 batch。同一张照片，和一批亮度均值 0.6 的照片分在一起，\(\mu_B\approx 0.6\)，它的激活 \(x_3=3.7\) 被减掉 0.6 后除以该批标准差；和一批亮度均值 0.2 的照片分在一起，\(\mu_B\approx 0.2\)，同一个 \(x_3=3.7\) 被减掉的是 0.2。两个 batch 对同一个激活产生两种不同的归一化输出。训练时 batch 每次随机重组，这个波动持续存在。

这种批噪声在训练中并非纯害。它在一定程度上充当了正则化——网络不能过度依赖某个激活的精确值，因为基准在不断变动。它被迫学习在多种偏移和尺度下都能工作的表示。但这同时意味着：训练过程中网络从未真正接触过一个``只依赖当前样本''的确定性函数。在训练态的视角下，每个样本的输出都是一个随机变量，其方差来自同 batch 中其他样本的波动。

推理时每次只来一个样本，batch 不存在。标准做法是改用训练期间通过指数移动平均积累的全局统计量：
\[
\hat\mu \leftarrow \alpha\hat\mu + (1-\alpha)\mu_B,
\qquad
\hat\sigma^2 \leftarrow \alpha\hat\sigma^2 + (1-\alpha)\sigma_B^2,
\]
\(\alpha\) 是动量，通常 0.9 或 0.99。推理函数终于变成了一个确定性的输入-输出映射——但它是训练时那个随机映射的某种期望近似，不是精确等价。

\subsection{全局统计量的质量：batch size 决定估计精度}

移动平均能不能准确反映真实的数据分布统计量，直接依赖训练时的 batch 大小。

假设你在一张 GPU 上用 batch size 4 训练了 100 个 epoch。每个 batch 只有 4 个样本参与 \(\mu_B\) 的计算。如果真实的通道均值是 \(\mu_{\text{true}}\)，方差是 \(\sigma_{\text{true}}^2\)，那么用 4 个样本估计均值，标准误差是 \(\sigma_{\text{true}} / \sqrt{4} = \sigma_{\text{true}} / 2\)。这批统计量在真实值两侧大幅摆动——每个 batch 给出一个相差可能很大的 \(\mu_B\)，动量平均只能减缓它、不能消除它。训练结束后 \(\hat\mu\) 中残留的方差仍然不小。

分布式训练中，问题以一种更隐蔽的方式复现。八张 GPU 各拿 batch size 32，梯度通过 all-reduce 求平均，等效 batch size 为 256——对优化器来说如此。但如果 BN 的 \(\mu_B,\sigma_B^2\) 只在每张卡内部计算而不跨卡同步，每张卡上的 BN 实际只看到 32 个样本的统计量。噪声水平仍然是 batch size 32 的水平，不是 256 的水平。这种不一致微妙但致命：优化器以为自己在用 256 的 batch 做稳定更新，BN 实际在靠 32 的 batch 做嘈杂的归一化。

\subsection{Layer Normalization：换一条轴做归一化，换一种取舍}

Layer Normalization 走了另一条路——它对每个样本内部的特征维求均值和方差，不跨 batch：
\[
\mu_{\text{LN}} = \frac{1}{D}\sum_{j=1}^D x_j,
\qquad
\sigma_{\text{LN}}^2 = \frac{1}{D}\sum_{j=1}^D (x_j - \mu_{\text{LN}})^2.
\]
每个样本的输出完全由自己决定，与同 batch 其他样本无关。

这意味着 LN 在训练态和推理态之间不存在 gap——同一个样本永远给出相同的归一化结果。对于 batch size 必须很小甚至为 1 的场景（NLP 微调、序列模型、在线推理），这一点是决定性的优势。

但 LN 也有代价。跨特征维的归一化会抹掉特征之间的绝对尺度差异。对于某些任务，这些差异本身就是信号——比如一层中某些神经元倾向于对特定模式强激活，另一些倾向于弱激活，这种相对大小携带了信息。LN 强制把它们拉平到零均值单位方差，后续层只能用 \(\gamma,\beta\) 恢复一个全局的尺度和偏移，不能恢复单个特征在单样本上的特异性尺度。

选择 BN 还是 LN，选择在张量的哪条轴上归一化，不是在选``更好的归一化技巧''——这两个选项对应着不同的假设：你认为通道间的统计一致性（BN 的跨 batch 共享尺度）更重要，还是单样本内部的自洽性（LN 的独立归一化）更重要。

\subsection{Dropout：每次前向随机拆掉一部分神经元}

Dropout 的随机源不同，但制造训练-推理 gap 的机制如出一辙。设保留概率为 \(q\)（常用 0.5）。训练时对每个激活 \(h_j\) 独立采样掩码 \(m_j \sim \text{Bernoulli}(q)\)，inverted dropout 计算
\[
\widetilde h_j = \frac{m_j}{q}h_j.
\]
除以 \(q\) 训练时校准一阶期望：
\[
\mathbb{E}[\widetilde h_j \mid h_j] = \frac{\mathbb{E}[m_j]}{q}h_j = \frac{q}{q}h_j = h_j.
\]
推理时关闭掩码，所有神经元以原值参与计算，不做放缩——因为训练时的 \(1/q\) 已经把期望校准到和推理一致。

一阶期望匹配在单个激活层面是精确的。但通过第一个非线性之后，事情就变了：
\[
\mathbb{E}[f(\widetilde h)] \neq f(\mathbb{E}[\widetilde h]),
\]
除非 \(f\) 恰好是仿射函数。Jensen 不等式告诉你，凸的 \(f\) 满足 \(f(\mathbb{E}[X])\le \mathbb{E}[f(X)]\)；对非凸非凹的激活函数（ReLU、GELU、tanh），偏的方向甚至不固定。经过几层累积，这个期望值缺口可能变得可观。关闭 Dropout 后的确定性推理网络，只是对所有 \(2^n\) 个可能子网络（\(n\) 为含 Dropout 的神经元总数）输出的一个近似——但一阶匹配不保证高阶匹配，更不保证输出分布匹配。

做一个类比：五个人准备小组汇报。每次排练随机缺席两人，剩下三人必须能独立讲清各自的逻辑——不能把关键结论全压在某个经常缺席的成员身上。缺席越多，剩下的人被迫承担越重，信息分布越均匀。这解释 Dropout 如何打破共适应——神经元不能指望特定的搭档一定在场。但反向风险也同样真实：如果团队本来就只有三个人，再随机缺一个，连基本内容都讲不完。模型容量小、数据已经稀缺、或者 BN 等归一化层已经在注入噪声时，较大的 Dropout 可能主要导致欠拟合——子网络的处理能力衰减太快，超出了``防止过拟合''换来的好处。

\subsection{训练态和推理态是两张不同的计算图}

BN 和 Dropout 共享的结构特征是：训练时做的事和推理时做的事不一样。使用它们的网络同时定义了至少两个函数：
\[
f_{\text{train}}(x, \text{batch}), \qquad f_{\text{eval}}(x).
\]
第二个函数不是第一个的某种``平均''——它是对训练系统的输出去掉了两个噪声源之后的一个近似。

最常见的出错方式不是梯度爆炸或 NaN，而是静默的功能偏移——loss 正常降、val 正常升，但部署后行为不对：

\begin{itemize}
\tightlist
\item
  保存模型权重时忘了保存 BN 的 \(\hat\mu, \hat\sigma^2\)。加载后 BN 用随机初始值或零做推理，每个通道的归一化基准彻底错位——但网络照常输出数值，不会报错。
\item
  微调阶段 batch size 设为 1 或 2，并且继续更新 \(\hat\mu, \hat\sigma^2\)。移动平均被极度嘈杂的统计量驱动，偏离预训练阶段积累的良好估计，推理时使用的是一个被污染的全局统计量。
\item
  验证时忘记切到 eval 模式，Dropout 仍随机丢弃神经元。验证曲线被注入不必要噪声，可能把好模型判为差模型——不是因为泛化差，而是因为评估时噪声遮住了真实性能。
\item
  BN 和 Dropout 叠加且顺序不同（BN 后 Dropout 还是反过来），训练态和推理态的统计差异量级不同。arXiv 上关于二者使用时序的结论时有矛盾，部分原因就是各实验在这一点上的设置不一致。
\end{itemize}

是否使用 BN 或 Dropout，不应该由``深层网络都需要它们''来决定。诊断的顺序比调参本身重要：训练初期 loss 是否震荡或不下降（BN 可稳定梯度）；有效 batch size 是否大到足以支撑可信的批统计量（太小就该考虑 LN 或 GroupNorm）；部署时是否天然逐样本推理（LN 的推理态和训练态一致）；训练数据与部署数据之间是否存在分布漂移（移动统计量在协变量偏移下会系统性失效）。归一化和 Dropout 可以改变优化地形和有效容量，但它们不能替代正确的数据划分、学习率诊断和独立的验证策略。二者的选择首先是两个训练-推理一致性工程的决策，其次才是正则化强度的调参问题。
