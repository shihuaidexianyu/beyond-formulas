\section{Bellman 方程与值迭代、策略迭代}
\label{sec:16-Control-and-Reinforcement-Learning/02-Reinforcement-Learning/02}

上一节把仓储调度写成了一个 MDP，现在要真的算出该往哪走。最直接的想法是把未来全部展开比较：往前看 10 步，每步 3 个动作，每个动作后可能落到 5 个状态之一，路径数是 \((3\times 5)^{10}\approx 5.77\times 10^{11}\)。一台每秒评估一百万条路径的机器要跑将近七天，而自动驾驶每秒要做几十次这样的决策。算力翻一万倍也没用，步数再加五层就回到原点——指数增长不是硬件能追上的东西。

退一步用贪心？两个状态就能把它戳穿。在状态 \(s\) 面前有两个按钮：``取走''立刻给 \(2\) 并结束；``等待''给 \(0\)，但确定进入状态 \(g\)，此后每步稳拿 \(1\)。取 \(\gamma=0.9\)，则

\[
V^*(g)=1+0.9+0.9^2+\cdots=\frac{1}{1-0.9}=10,
\]

于是等待的价值是 \(0+0.9\times 10=9\)，远高于取走的 \(2\)。贪心比的是即时奖励，永远不肯为一张通往高价值区域的门票先垫一笔钱。

穷举算不完，贪心看不远。这一节要说明，出路既不是更快地穷举，也不是更聪明的贪心，而是换一个提问方式：不去求``最优的一整条路径''，去求一个满足自洽条件的\emph{值函数}。那个自洽条件就是 Bellman 方程，而它是一个不动点方程。

\subsection{回报自带一层递归，方程由此而来}

一切都从一个纯代数事实开始：

\[
G_t = R_{t+1} + \gamma G_{t+1}.
\]

这里没有用到任何环境假设，只是把求和拆成第一项加剩下的。它的意义在于：如果有人能告诉你从下一步起的最优剩余价值，当前决策立刻退化成单步比较——只是贪的对象从即时奖励 \(r\) 变成了 \(r+\gamma\times\)（未来价值）。

在策略 \(\pi\) 下取条件期望，按下一动作和下一状态展开：

\[
V^\pi(s) = \sum_a \pi(a \given s) \sum_{s'} P(s' \given s, a)
\bigl[ r(s, a, s') + \gamma V^\pi(s') \bigr].
\]

注意右端出现了 \(V^\pi\) 自己。这不是一路向前算完就收工的递推式，它是一组联立方程：每个状态的值依赖别的状态的值，那些状态的值又绕回来依赖它。写成矩阵形式，

\[
V^\pi = r^\pi + \gamma P^\pi V^\pi,
\qquad\text{即}\qquad
(I - \gamma P^\pi) V^\pi = r^\pi.
\]

\(\gamma<1\) 且状态有限时，\(P^\pi\) 的谱半径为 \(1\)，\(\gamma P^\pi\) 的谱半径为 \(\gamma<1\)，所以 \(I-\gamma P^\pi\) 可逆，

\[
V^\pi = (I - \gamma P^\pi)^{-1} r^\pi.
\]

策略一旦固定，决策问题就塌缩成一条 Markov 链上的线性方程组。值函数不是需要凭空猜的东西，方程把它钉死了。实际计算当然不会去求这个逆，但这个式子确立了存在性和唯一性。

\subsection{最优性方程比期望方程多一个 max}

最优状态值定义为 \(V^*(s)=\sup_\pi V^\pi(s)\)。它满足什么方程？动态规划原理给出答案：从 \(s\) 出发的最优路径，在选完第一个动作、拿完奖励、落到 \(s'\) 之后，余下那段必须仍是从 \(s'\) 出发的最优路径。否则把余段替换成更优的，整条路径就更优，与``最优''矛盾。于是

\[
V^*(s) = \max_a \sum_{s'} P(s' \given s, a)
\bigl[ r(s, a, s') + \gamma V^*(s') \bigr].
\]

在有限动作集下，逐状态取到最大值的那些动作拼起来，就是一个确定性平稳最优策略 \(\pi^*(s)=\argmax_a(\cdots)\)。动作值版本把动作提到前面：

\[
Q^*(s, a) = \sum_{s'} P(s' \given s, a)
\bigl[ r(s, a, s') + \gamma \max_{a'} Q^*(s', a') \bigr].
\]

知道 \(Q^*\) 之后，最优动作直接是 \(\argmax_a Q^*(s,a)\)，用不到转移核 \(P\)。第四节要转向 Q 学习，理由就埋在这里：\(Q\) 把决策和模型解耦了。

拿前面那个两状态例子对一遍。状态 \(g\) 只有一个动作，最优性方程变成一元一次方程 \(V^*(g)=1+0.9V^*(g)\)，解得 \(V^*(g)=10\)——不是把无穷级数加出来的，是解出来的。再看 \(s\)：

\[
\begin{aligned}
Q^*(s, \text{取走}) &= 2 + 0 = 2, \\
Q^*(s, \text{等待}) &= 0 + 0.9 \times V^*(g) = 9,
\end{aligned}
\]

所以 \(V^*(s)=9\)，最优决策是等待。这里值得停一下：\(V^*(g)=10\) 这一个数，浓缩了从 \(g\) 出发的全部无限长未来。\(s\) 的方程要用到 \(g\) 时，只需要写一行 \(r+\gamma\times 10\)。动态规划的压缩力量就在这一步——用一个标量替掉一整棵子树。

把 \(\gamma\) 换成 \(0.1\)，则 \(V^*(g)=1/0.9\approx 1.11\)，等待的价值只剩 \(0.1\times 1.11\approx 0.11\)，取走的 \(2\) 重新胜出。\(\gamma\) 控制的是有效视界的长度，它换掉的是最优策略本身。

\subsection{值迭代是压缩映射迭代，收敛速率写在 \texorpdfstring{\(\gamma\)}{gamma} 上}

定义 Bellman 最优性算子

\[
(TV)(s) = \max_a \sum_{s'} P(s' \given s, a)
\bigl[ r(s, a, s') + \gamma V(s') \bigr],
\]

值迭代就是取任意有界初值 \(V_0\)，反复做 \(V_{k+1}=TV_k\)。这个迭代会不会在两个值之间来回振荡，今天的 max 指东、明天指西？

不会，理由是 \(T\) 在上确界范数下是压缩映射：对任意有界 \(V,W\)，

\[
\norm{TV - TW}_\infty \le \gamma \norm{V - W}_\infty.
\]

证明骨架只有三步。先用``两个最大值之差不超过逐项差的最大值''这条不等式，把 \(\abs{(TV)(s)-(TW)(s)}\) 压到某个动作 \(a\) 上；再把该动作下的差写成 \(\gamma\sum_{s'}P(s'\given s,a)\abs{V(s')-W(s')}\)，即时奖励项相消；最后用 \(P(\cdot\given s,a)\) 是概率分布、加权平均不超过上确界，得到 \(\gamma\norm{V-W}_\infty\)。条件对账：要求奖励有界（否则 \(\norm{\cdot}_\infty\) 无意义）、\(\gamma<1\)（否则压缩系数不小于一）、\(\max_a\) 能取到（有限动作集自动成立，连续动作要另加紧致性与可测选择的条件）。

这三个条件配上有界函数空间在上确界范数下的完备性——正是\hyperref[sec:12-Real-Analysis-Support/03-Topology-Basics/03]{``完备性让逼近留在空间内''}所保证的那件事——Banach 不动点定理就能一次性给出三个结论：\(T\) 有唯一不动点，它就是 \(V^*\)；任意有界初值都收敛到它；误差按几何级数下降，

\[
\norm{V_k - V^*}_\infty \le \gamma^k \norm{V_0 - V^*}_\infty.
\]

这是\hyperref[sec:08-Numerical-Analysis/02-Root-Finding/02]{``不动点与 Newton 法''}里那套迭代格式在函数空间上的版本，只是这里的压缩系数不用估计，它明写在折扣因子里。

图的左半边解释了为什么不必担心振荡：迭代点在球内怎么跑都行，约束只作用在半径上。右半边把代价摆了出来。初始偏差取 \(100\)，\(\gamma=0.9\) 时 10 轮后剩 \(34.9\)、50 轮剩 \(0.52\)、100 轮剩 \(0.0027\)；换成 \(\gamma=0.99\)，100 轮之后还剩 \(36.6\)。同样一百轮，质量从接近机器精度退化到几乎没动。

这就是折扣因子的取舍全貌：\(\gamma\) 越接近 1，有效视界越长、远期奖励越能传回来，同时压缩越弱、误差衰减越慢。它不是实现效率的问题，而是信息沿状态图传播速度的上限。实际停机通常查 Bellman 残差，而残差与真误差的关系也带着同一个因子：

\[
\norm{V_k - V^*}_\infty \le \frac{\norm{TV_k - V_k}_\infty}{1 - \gamma}.
\]

\(\gamma\) 逼近 1 时分母极小，残差看着不大，离真解可能还很远。只盯着相邻两轮里几个状态没怎么变就宣布收敛，是这一步最常见的误判。

\subsection{策略迭代与值迭代的差别只是每轮评估多少}

值迭代每轮做一次备份就顺手改进。策略迭代把两件事分开：

\begin{enumerate}
\tightlist
\item
  策略评估：对当前 \(\pi\)，解线性方程组 \(V^\pi = r^\pi + \gamma P^\pi V^\pi\)，一路解到底；
\item
  策略改进：对每个状态做一步前瞻贪心，
  \[
  \pi_{\text{new}}(s) \in \argmax_a \sum_{s'} P(s' \given s, a)
  \bigl[ r(s, a, s') + \gamma V^\pi(s') \bigr].
  \]
\end{enumerate}

策略改进定理保证新策略不差于旧策略。骨架是这样的：\(V^\pi\) 已经算清了``此后一直走 \(\pi\)''的全部未来，把第一步换成前瞻值更高的动作、尾部照旧，一步的回报不降；再把这个论证沿时间反复代入，整条轨迹的期望回报也不降。条件对账：需要 \(\gamma<1\) 使代入过程的余项趋于零，需要 \(V^\pi\) 是精确解（评估没解到底时结论要打折），需要贪心在每个状态都取到最大值。

对有限状态动作集，确定性策略只有有限多个，每轮要么严格改善要么已经最优，所以有限步终止。策略迭代经历的策略数通常远少于值迭代的轮数，但它每轮的评估成本高得多。

两者其实是同一个不动点问题的不同求解节奏。评估解到底就是策略迭代，评估只做一轮就是值迭代，中间地带是修正策略迭代：跑 \(m\) 轮评估再改进，\(m\) 是一个连续可调的旋钮。它们求的都是 \(T\) 的那个不动点，区别只在每轮往评估里投多少算力。工程上怎么选，取决于评估一次有多贵——状态少、线性求解便宜时偏策略迭代，状态多、只能扫描时偏值迭代。

\subsection{方程正确不等于方程可解}

上面所有保证都挂在一组具体条件上：模型已知，每次备份都能对 \(P(s'\given s,a)\) 精确求期望；状态动作空间可以扫描，或者期望至少可以算；环境是 Markov 的且规律不随时间变；\(\gamma<1\)，或者任务终止且满足吸收条件。

状态数一大，逐状态扫描就撞上维数灾难。这是离散表格法的固有代价，不是算法写坏了。连续状态装不进一张表；连续动作下的 \(\max_a\) 本身可能就是一个高维非凸优化。动态规划给了你正确的方程，没承诺这个方程在现实规模上解得动。

把``模型已知''这一条去掉，方程一字不改，但期望没法精确算了。你手里只剩单步样本，而

\[
R_{t+1} + \gamma \max_{a'} Q(S_{t+1}, a')
\]

只是 Bellman 右端的一个带噪观测。把确定性的不动点迭代换成用样本驱动的随机逼近，就走到了下一节。方程还是那个方程，变的是你能不能算清那个期望。
