\section{在对数域中稳定计算概率}
\label{sec:08-Numerical-Analysis/07-Numerical-Methods-for-ML/01}

一个三分类模型在最后一层输出了三个分数，还没送进 softmax：
\[
x=(1000,1001,999).
\]
看不出什么问题——都是三位数，彼此也差不多。按照 softmax 的定义，第一个类别的概率是
\[
p_1=\frac{e^{1000}}{e^{1000}+e^{1001}+e^{999}}.
\]
用普通的双精度浮点数（float64）算 \(e^{1000}\)。float64 能表示的最大值约 \(1.8\times10^{308}\)，而 \(e^{1000}\approx 2\times10^{434}\)——分子分母一起溢出为正无穷，然后无穷除以无穷得到 NaN。一个完全合法的数学公式，三个合法输入，程序崩溃了。

你可以换成更高精度——float128 的上限约 \(10^{4932}\)，能扛住 \(e^{1000}\)，但 \(e^{2000}\) 照样溢出。高精度只是把失败推迟到更大的输入，没有改变算法的脆弱结构。真正的问题是：这个计算路径把指数算了出来、存了下来，而浮点数根本不是为了容纳 \(e^{1000}\) 这类数字而设计的。

好在 softmax 有一个被它的数学形式直接保证的性质：它对所有输入加同一个常数保持不变。
\[
\frac{e^{x_i}}{\sum_j e^{x_j}} = \frac{e^{x_i-c}}{\sum_j e^{x_j-c}}.
\]
这来自分子分母同乘 \(e^{-c}\)。常数 \(c\) 可以任意选择，概率恒等。于是我们有了自由：选一个 \(c\) 把所有指数拉回浮点数能安全处理的区间。

最好的选择是 \(c=m=\max_j x_j\)。这样一来最大的指数自变量变成了零——\(e^0=1\) 是世界上最安全的指数计算——其余都 \(\le 0\)，指数值落在 \((0,1]\)。刚才的例子中：
\[
x-m=(-1,0,-2),
\]
三个指数变成了
\[
(e^{-1},1,e^{-2})\approx(0.3679,1,0.1353),
\]
归一化后
\[
p\approx(0.2447,0.6652,0.0900).
\]
这不是对 softmax 的近似或 hack；在精确算术中，平移前后的公式完全相等。改变的不是数学，而是通往答案的计算路径。

\subsection{Log-sum-exp：对数和到指数空间的稳定桥梁}

概率模型中反复出现这样的需求：先算一堆数的指数和，再取对数。log-sum-exp（LSE）就是这个操作：
\[
\operatorname{LSE}(x)=\log\sum_{i=1}^n e^{x_i}.
\]
如果先算指数和再取对数，溢出的路线和 softmax 一模一样。但同样可以用平移恒等式：
\[
\operatorname{LSE}(x)
=m+\log\sum_{i=1}^n e^{x_i-m},
\qquad m=\max_i x_i.
\]
平移后，最大项恰好对应 \(e^0=1\)，所有项都在 \((0,1]\) 之间，求和结果在 \(1\) 和 \(n\) 之间——一个浮点数完全轻松驾驭的范围。取对数后落在 \([0,\log n]\)，再加回 \(m\) 即得最终结果。

这个分解带来了一个很有用的不等式。平移后的和满足
\[
1\le \sum_i e^{x_i-m}\le n,
\]
三边取对数（中间正是 \(\operatorname{LSE}(x)-m\)）再加回 \(m\)：
\[
\max_i x_i
\le \operatorname{LSE}(x)
\le \max_i x_i+\log n.
\]
LSE 可以理解为最大值的\"光滑化\"：当某一项远大于其他项时，LSE 几乎就是那个最大值；当多项接近时，额外的 \(\log n\) 以内的项记录了这些竞争者们的共同贡献。

更有趣的是 LSE 的梯度：
\[
\frac{\partial\operatorname{LSE}}{\partial x_i}
=\frac{e^{x_i}}{\sum_j e^{x_j}}
=p_i,
\]
正好是 softmax 的输出。softmax 和 LSE 的关系不是巧合——softmax 就是 LSE 对输入的敏感度。这一对\"值 + 梯度\"的关系，和凸优化中\"函数值—次梯度\"、强化学习中\"价值函数—策略\"是同一类对偶结构。

\subsection{不要先算出概率，再对它取对数}

分类模型训练时，损失函数要的是正确类别 \(y\) 的负对数概率 \(-\log p_y\)。很多人会自然写成：先 softmax、后取 log。这两步分开做，中间生成了整张概率表——而概率表里的极小项可能已经下溢为零。对零取对数是 \(-\infty\)，训练梯度当场崩溃。

更可靠的做法是直接由 logits 计算：
\[
-\log p_y
=\operatorname{LSE}(x)-x_y.
\]
这个表达式跳过了概率表这个中间环节。即使 \(p_y\) 本身已经小到浮点数无法区分零，\(x_y-\operatorname{LSE}(x)\) 仍可能是一个完全正常的负数。同样的，稳定的 log-softmax 应直接写成
\[
\log p_i=x_i-\operatorname{LSE}(x),
\]
而不是先算 softmax 再取 log。

成熟的数值库（如 PyTorch 的 `log_softmax` 和 `cross_entropy`）把这些步骤融合在一起，既不生成整张概率表，也不走多余的舍入路径。这背后是一个反复出现的数值设计原则：如果你最终需要的是对数量，就不要绕道经过概率空间；中间量越早被变换到对数域，可表示的范围越宽而不损失语义。

\subsection{下溢不总是灾难，不知道自己在丢失什么才是}

用最大值平移后，仍然可能有极小项下溢为零。比如 \((0,-1000)\) 在 float32 下会得到概率 \((1,0)\)。但这里损失的信息——第二个概率大约是 \(e^{-1000}\)——对归一化和的贡献本来就可以忽略。下溢本身不是 bug；在不应该下溢的地方下溢才是。

真正危险的几种情况：

\begin{itemize}
\tightlist
\item
  平移前让大指数直接上溢——这是最致命的，因为 Inf 之后一切运算都失去了数值意义；
\item
  需要对极小概率取对数，却先把它舍入成零——\(-\infty\) 不是\"一个很小的数\"，它会沿着计算图炸掉梯度；
\item
  低精度求和时让大量小贡献过早消失——这也是\hyperref[sec:08-Numerical-Analysis/01-Floating-Point-Arithmetic/02]{``求和的艺术''}中讨论过的累积精度问题；
\item
  把一个没有合法概率语义的输入强行归一化——这属于语义错误，下一段展开。
\end{itemize}

\subsection{Mask：数值稳定不能替业务语义做决定}

序列模型中经常需要 mask 掉填充位置。自然做法是把无效位置的 logits 设成 \(-\infty\)，这样 softmax 之后那些位置的概率自动为零，不影响有效位置。

稳定实现对此的处理流程是：先找每行的有效最大值（跳过 \(-\infty\)），再平移，再对有效位置求指数和。只要一行中至少有一个有效位置，整个流程返回有限且有意义的概率。

但如果一整行都被 mask 掉——所有 logits 都是 \(-\infty\)——会发生什么？最大值是 \(-\infty\)，平移时出现 \(-\infty-(-\infty)\)，这在浮点标准中是 NaN。此时不存在唯一的\"正确概率\"。调用者必须明确：这一行应该跳过、应该报错，还是应该填成均匀分布？数值技巧可以提供几种处理选项，但不能代替你回答\"在你这任务中，一整行都被遮住意味着什么\"。

混合精度训练中还有一个容易被忽略的细节：输入 logits 可以留在低精度（如 fp16），但最大值归约、指数求和和损失累加应该放在更高精度（如 fp32）中进行。减去最大值解决了动态范围问题，但不会自动恢复低精度已经丢失的有效数字。

\subsection{一组从数学性质出发的测试}

稳定概率计算的实现是否正确，最好的测试不是抄几组期望输出——抄错了你也看不出来。应该用数学恒等式去验证：

\begin{itemize}
\tightlist
\item
  所有 logits 加同一常数后，softmax 概率完全不变，LSE 恰好增加该常数；
\item
  每行输出的概率全部非负且总和约等于 1（允许舍入量级的偏差）；
\item
  极端大的 logits（如 \(10^4\)）、极小 logits（如 \(-10^4\)）、全等 logits、单有效 mask 的输入——都返回有限结果而不是 Inf/NaN/负概率；
\item
  log-softmax 的结果与直接由 LSE 公式得到的对数概率一致；
\item
  全 mask 行、空输入、含 NaN 的输入——行为符合你定义的接口约定，而不是偶然返回了某个看似合理的数字。
\end{itemize}

这些检查的威力在于它们来自 softmax 和 LSE 的数学定义，不是来自某个特定实现的参考输出。任何实现只要满足数学性质，就自动通过这些测试；而如果某个实现通过了抄来的期望输出却通不过平移不变性，它的 bug 只是恰好没在抄来的例子中被触发而已。\"平移前后概率不变\"这一个数学性质，比一百个硬编码的测试用例更能揪出轴错误、广播错误和 mask 逻辑错误。
