\section{误差如何产生与放大}
\label{sec:08-Numerical-Analysis/01-Floating-Point-and-Error/02}

你写了一段代码，跑出来答数偏离预期几个数量级。你打开调试器，把中间变量一个个打印出来。问题出在哪一行？答案是：可能不在任何一行。

一次数值计算的误差不是一个来源。它至少有三个独立来源，常常叠加在一起，用同一个症状——「答案不对」——呈现给你。把三个来源拆开，才能知道该改代码、该改公式、还是该改问题定义。

\subsection{先问：误差相对于什么}

讨论误差之前，你得先选一把尺。

若真实值为 \(x\)，近似值为 \(\hat x\)，绝对误差是
\[
e_{\mathrm{abs}} = |\hat x - x|.
\]
这是一把固定的尺。它适合衡量有自然物理尺度的量——长度、质量、时间。也适合衡量接近零的量，因为此时相对误差会爆炸，绝对误差反而是唯一稳定的度量。

相对误差是
\[
e_{\mathrm{rel}} = \frac{|\hat x - x|}{|x|}, \qquad x \ne 0.
\]
这把尺跟着被测量一起缩放。把 \(10^6\) 算成 \(10^6 + 1\)，相对误差才 \(10^{-6}\)；把 \(10^{-8}\) 算成 \(2 \times 10^{-8}\)，绝对误差极小，相对误差却已经翻倍。

当真值 \(x\) 恰好为零或极其接近零，相对误差的定义直接失效。这不是公式的缺陷，而是「相对于零」这件事本身就缺乏稳定的评估基准。零没有尺度，无法定义相对变化。实践中常见做法是使用绝对与相对容差的组合：
\[
|\hat x - x| \le a_{\mathrm{tol}} + r_{\mathrm{tol}} |x|.
\]
当 \(x\) 大到相对容差主导时，它近似于相对误差检查；当 \(x\) 小到绝对容差主导时，它避免对零附近的量提出不合理的精度要求。

\subsection{舍入误差与截断误差不是同一件事}

初学数值分析的人常把两种误差搅在一起：「反正都是误差，结果都不对」。分不清的代价是花大量时间降低一种误差，却被另一种误差淹没了收益。

\textbf{舍入误差}来自把精确实数映射到有限的浮点集合。每次基本运算后，结果必须落回最近的可表示数。上一节讨论的 unit roundoff \(u\) 就是每次舍入的相对误差上限。

\textbf{截断误差}来自用有限过程替代无限或连续对象。即便你有一台能存储无限位的完美计算机，截断误差依然存在。比如：
\[
e^x \approx 1 + x + \frac{x^2}{2},
\]
你省略了 Taylor 级数的第三项及之后所有项。用差商 \((f(x+h)-f(x))/h\) 近似导数，用有限步 Euler 法推进微分方程——这些都是在做「无限换成有限」的交易，都会产生截断误差。

更重要的是，减小截断误差的手段往往跟舍入误差打架。步长越小，截断误差通常越小，但运算次数增多，舍入误差逐步累积。Taylor 项数越多，截断误差越小，但每多加一项就多几次浮点运算，也多了几次舍入的机会。数值方法的最优参数——最优步长、最优项数——通常落在两种误差的交叉点上。一味追求「越小越细越精确」，很可能越过交叉点，反而让总误差回升。

\subsection{灾难性消去：当减法掀开高位后面的伤疤}

这是数值计算中最常见的「意外」，也是新手最容易踩的坑。

假设你有两个大数，各自都带着一些微小的相对误差。把它们相减后，真值变得很小；但在做减法的那个瞬间，输入数据里藏在有效位末端的那些绝对误差，相对于小结果来说，突然变得巨大。

一个经典例子：计算 \(1 - \cos x\)，当 \(x\) 很小时。

\(\cos x \approx 1 - x^2/2\)，\(1\) 和 \(\cos x\) 在前几位数字几乎一模一样。相减后，两个数里分别存在的绝对误差——也许只有末几位——被保留了下来，而真值只有 \(x^2/2\) 这个量级。如果把减法想象成揭露两个数高位的差，那么误差就是高位差被取走后，留在后面的噪声。

解决方法是换一条数学上等价、数值上不同的路：
\[
1 - \cos x = 2 \sin^2(x/2).
\]
右边直接在 \(x^2\) 的数量级上计算，不再有相近大数相减的步骤。同样正确的数学，选择不同的表达式，数值结果可以天差地别。

再举一个例子。大 \(x > 0\) 时计算
\[
\sqrt{x^2 + 1} - x.
\]
\(\sqrt{x^2 + 1}\) 和 \(x\) 非常接近，减法又是一场灾难。有理化后得到
\[
\frac{1}{\sqrt{x^2 + 1} + x},
\]
不仅回避了消去，还直接暴露结果约等于 \(1/(2x)\)，更清晰地展示了渐近行为。

一条重要的区分：相减操作本身如果是按浮点规则正确舍入的，它在数值上可能是稳定的。真正病态的是「由两个近似大数恢复一个微小的差值」这件事本身——你丢失的信息在减法之前就已经在那些大数的末位里了。想补回来，靠的是换表达式，不是换精度。

\subsection{小量在求和中如何一个接一个地消失}

大量小数的累加是另一类经典陷阱。你有一个很大的部分和 \(S\)，然后往上面加一个小数 \(x\)。如果 \(x\) 的绝对值小于 \(S\) 的 ulp 的一半，那么 \(S + x\) 舍入回去还是 \(S\)。相当于 \(x\) 被吞掉了。

一百万个 \(10^{-8}\) 的累加，理论上是 \(10^{-2}\)。但如果你从第 0 开始挨个加，算到某个部分和比如 \(10^{-4}\) 之后，再往上的每个 \(10^{-8}\) 都可能因为低于当前 ulp 而被无声吞没。最终结果可能远小于理论值，偏差不是几个 ulp，而是几个数量级。

修正策略有三条：

\begin{itemize}
\tightlist
\item 按绝对值从小到大排序再累加——让小量先长成大块，再跟更大的和汇合。
\item 成对求和（pairwise summation）：把累加组织成二叉树，每个父节点合并两个规模相近的子节点。累加深度的降低把舍入误差从 \(O(n)\) 改善为 \(O(\log n)\)。
\item Kahan 补偿求和：维护一个补偿变量，记录每次加法中被丢掉的小量，在下一次加法中把它补回去。
\end{itemize}

这些策略有效的前提是：最终和本身的条件数不过于恶劣。如果你有正负大数互相抵消的情况，最终和可能是大数差的一个微小残差——那属于问题本身敏感，不是求和技术能凭空恢复的。

\subsection{误差传播：导数或 Jacobian 是扩音器}

输入有误差时，函数输出的误差方向取决于斜率。对于一元函数 \(y = f(x)\)，若输入有小扰动 \(\Delta x\)，一阶 Taylor 展开直接给出：
\[
f(x + \Delta x) - f(x) \approx f'(x) \Delta x.
\]
导数 \(|f'(x)|\) 若很大，输入末位的一点扰动会被放大成输出的明显变化；若很小，则输入噪声被压缩。

多元情形下，扰动被 Jacobian 矩阵 \(J_f(x)\) 传播：
\[
\Delta y \approx J_f(x) \Delta x,
\]
其中 \(\Delta x\) 是输入的扰动向量。Jacobian 不仅能缩放扰动的大小，还会改变扰动的方向——某个方向上的输入扰动可能被剧烈放大，另一个方向上可能几乎过滤干净。

这个事实意味着：计算误差不是机器精度 \(u\) 乘以一个固定常数。它取决于你站在函数的哪个点上——当前点的斜率或 Jacobian 才是那个扩音器的旋钮位置。这也是下一节要讨论的条件数的出发点。
